# 教师审核超过 60 分钟失败修复与部署

2026-09-14，香港生产环境。数据库迁移已部署并验证。

## 原因与修复

`0072_exercise_limits` 已允许每条记录按快照使用最高 1440 分钟的单次上限，但 `v81_credit_projections.eligible_minutes` 仍沿用最初的 0–60 分钟约束。审核通过和退回补证都会重算该学生的学时，因此两条路径均可能触发 PostgreSQL `23514`，令整个审核事务回滚。

新增迁移 `0077_credit_projection_minutes`，在事务内将这一约束调整为 0–1440 分钟。保留非负数、`credited_minutes <= eligible_minutes`、非空、主键和外键校验。迁移不改业务数据、规则快照、审核结论或学时计算算法。使用 3 秒锁等待和 30 秒语句超时；失败时事务回滚。新 SQL 文件固定 LF，避免 Windows 换行转换改变迁移校验和。

- 使用旧的 60 分钟约束时，65 分钟审核通过、76 分钟退回补证均复现 HTTP 500；应用新迁移后通过。
- 7 项真实 HTTP/PostgreSQL 回归通过：65/76 分钟的两种审核动作、历史空上限继续封顶 60、1440 分钟快照、课程目标重新分配。检查重复请求幂等、过期版本冲突、仅一条通知、原始运动事实和规则快照保留；负数、1441 分钟和计入数大于可计入数仍被数据库拒绝。

## 另一个已确认的配置事实

两条记录都是 `COURSE_RELATED`，所属课程却配置为 `course_target = 0`、`general_target = 1200`。在当前配置下，即使审核通过，计算结果也是可计入 65/76 分钟、实际计入 0 分钟，原因 `CREDIT_LIMIT`。此配置与本次数据库异常独立，需要教师按课程要求核对目标分配或记录分类；此次未擅自修改。
