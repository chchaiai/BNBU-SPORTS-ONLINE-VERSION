# 补练提交截止修复与验证

## 问题与修复

真实网页授权补练后，学生已经开始会话，教师撤销授权，学生结束会话并上传材料，提交却返回 `409 COURSE_DEADLINE_PASSED`。结束操作本身成功。

原因：课程发布把常规截止时间同步到旧课程投影；记录提交只检查该字段，没有识别会话开始时保存的补练授权来源。原后端测试只将新版规则的常规截止设为过去，旧字段仍在未来，未能覆盖真实发布后的状态。

修复将提交校验放在原事务内，读取准确的会话补练来源，核对组织、课程、成员，以及开始时处于授权窗口且未被撤销的事实。合法补练按收尾截止判断；撤销后的新开始仍禁止。原有成员、课程、学期校验保留。

## 验证边界与交接

测试课程的历史时间表由明确标注的数据库夹具准备，授权与运动操作走实际服务。相机为浏览器合成设备，短时运动计入为零；这些证据不代表真实运动达到门槛，也不代表历史课程由网页发布。

原失败记录在私有忽略目录保存定位信息；新网页复测使用独立 `live-makeup-retest` 夹具，不覆盖原失败会话。第 41 次完整 Docker 回归通过：101/101、25 套件、0 失败/跳过；类型检查通过，219/219 启用接口成功响应、253/253 错误/权限响应、34 个按策略拒绝的接口覆盖通过。原始日志见 [完整回归](docker-fortyfirst-20260909.txt)，[接口覆盖](runtime-conformance-fortyfirst-20260909.md)。网页补练主体与撤销后禁止新开已分段验证，详见下节。全新课程目标和运动参数表单仍等待此前已发出的 UI 最小调整问题回复；整体任务未完成。
