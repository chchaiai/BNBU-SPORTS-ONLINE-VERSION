# 游泳预受理与错误提示修复交接

## 根因与变更

诊断编号 `01a09e40-0be9-748f-940e-53abecc1dc81` 已证实拒绝原因 `SWIM_INTAKE_REQUIRED`；详见同目录诊断记录。

- 学生 Web 在实时游泳提交前，明确要求真实的运动前、运动后照片各至少一张。照片阶段随本机草稿保存；结束后新拍照片不能标作运动前。游泳项目同时兼容本机小写值和服务器大写值。
- 新流程：建立记录草稿 → 为媒体登记 ID 与 SHA-256 → 调用现有 swim-intake 预受理 → 上传、确认、绑定和等待媒体验证 → 正式提交。视频标作 OTHER。历史补录和补证复用原流程。
- 预受理前查询已有批次；请求发送前保存并锁定本机材料。响应丢失后按服务器批次恢复，不能换文件。明确的受理拒绝解除本机锁定；上传进度在失败时也保存。首次受理成功后更新曾缓存旧失败的提交幂等编号；修改延迟说明时使用与新请求对应的编号。
- 支持填写延迟原因；超过正常15分钟受理或续传期限时交教师审核，24小时延迟提交边界仍由后端判断。
- 后端只向客户端传出明确允许的8种游泳 `details.reason`。客户端以中英文显示具体处理方法，替代误导性的“资料格式不正确／修正标记的字段”。内部未知 reason 不公开。

## 接口、数据库、页面

复用 GET/POST `/api/v1/exercise-records/{recordId}/swim-intake`、现有媒体上传接口和 POST `/api/v1/exercise-records/{recordId}/submit`，不新增端点。错误 details 新增可选 reason，当前开发 OpenAPI 及生成产物同步；没有进行正式 Contract 版本发布。

无数据库迁移。继续使用现有 `v81_swim_intakes`、`v81_swim_intake_items` 与媒体哈希锁定关系。页面增加照片阶段与延迟原因输入，并在批次受理后锁定拍摄、替换、删除和阶段编辑。
