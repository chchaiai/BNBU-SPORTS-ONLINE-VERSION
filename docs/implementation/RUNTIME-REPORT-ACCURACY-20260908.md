# 运行时验收报告准确性修复（2026-09-08）

问题：check-runtime-conformance-report.mjs 在缺少请求证据甚至有无效响应时，仍将接口 completionStatus 写成 IMPLEMENTED_AND_CONFORMANT；完全没有响应的停用入口也被标成 INTENTIONALLY_DISABLED_VALIDATED；Markdown 固定声称“Not implemented 0”。这会使交接报告误导读者，虽然命令退出码本身仍失败。

修复：只有有效响应进入成功/错误状态统计。报告区分未观测、只有成功、只有错误、无效响应、停用入口意外成功、两类有效响应完整验证、停用拒绝完整验证。未完成运行时验证一律 RUNTIME_VALIDATION_INCOMPLETE，完整验证仅标记 RUNTIME_CONFORMANT，不宣称已完成全部业务。汇总新增完整/不完整/未观测数量、整体门禁结果、失败条目；JSON 保留失败原因。

未降低原有失败门禁，仍要求启用接口成功与错误双向证据、停用接口拒绝且无成功、接口清单数量一致。旧清单 126 对当前协议 249 的缺口继续保留。

Docker 完整单元测试 246/246，通过四个新增报告回归：无证据、单向成功、无效响应/停用入口成功、全部有效证据。证据 docker-runtime-report-unit-20260908.txt。

完整 E2E 当前结果和逐接口报告另附：docker-backend-e2e-full-fourth-20260908.txt、runtime-conformance-current-20260908.json、runtime-conformance-current-20260908.md。这些是当前本地验收证据，不能当作云端上线或三端完整业务验收。

第四轮完整结果：13 套件、69/69 用例通过；802 条响应均符合协议，0 无效响应。全接口门禁失败 126 项，退出 1。按尚未更新的启用/停用清单，109 个启用接口具备成功及错误证据，17 个停用接口具备拒绝证据；123 个接口验证不完整，其中 1 个未观测。失败条目比第三轮 136 减少 10，对应帮助与反馈的成功响应纳入。未更新清单的业务分类不可直接用作最终功能状态。原始日志重复列出门禁失败，是标准命令与额外 --write 导出各执行一次检查，不是两轮 E2E。
