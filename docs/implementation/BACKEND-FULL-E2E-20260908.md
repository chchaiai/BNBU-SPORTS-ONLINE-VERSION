# 后端完整 HTTP E2E 首轮（2026-09-08）

在独立 bnbu-v81-full-integration Docker 环境执行 `integration-tests npm run test:e2e`。该命令先构建，再串行运行 12 个测试套件；连接已完成 57 个迁移的专用 tmpfs PostgreSQL。浏览器数据库不参与清理。

结果：退出 1，62 项测试，15 通过、47 失败、0 跳过，测试阶段约 48.8 秒。原始证据为 `docker-backend-e2e-full-first-20260908.txt`。这是真实 HTTP/PostgreSQL 测试；部分外部存储和邮件依赖由套件替身提供，不代表腾讯云验收。

已定位的原因与后续处理：

- `access-token.guard.ts` 对教师/管理员要求现行账号安全记录，缺失记录按首次改密未完成拒绝。旧 `seedFoundationFixture` 未建立这项数据，因此 `/me` 等出现 403；应为业务测试准备符合现行规则的账号，同时保留缺失记录/首次改密拒绝测试，不能放宽产品保护。
- 管理员还需要现行管理权限记录。必须依据每项测试需要设置身份与权限，不能把所有管理员测试统一改成无限权限。
- auth 套件硬编码受保护接口数量 112，现行实际 235；应按当前协议验证每条接口，保留覆盖完整性。
- auth/teaching 套件仍写入 READ_ONLY，数据库当前只允许 NORMAL/MAINTENANCE；沿用现行业务规则更新场景。
- 响应校验钩子报告多处 403 未在协议声明。需要核对首次改密和权限拒绝路径的合同响应，不能禁用校验钩子。
- 其他旧流程和断言尚未逐项确认原因，47 项失败不等同于 47 个产品缺陷，也不能全部归为旧测试问题。

本轮没有修改产品或测试断言。完整运行失败后，脚本没有执行最终运行覆盖汇总；不能声称全接口响应一致性通过。下一步从共用测试账号前置条件和认证套件开始修复，再重新执行完整 E2E，并保存独立复测证据。

总体目标仍在进行：Draft 协议诊断、完整 E2E 和三端业务覆盖尚未全部通过。
