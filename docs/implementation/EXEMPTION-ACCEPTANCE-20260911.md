# 学生“我的”免测与免打卡真实验收

## 结论

已完成本地真实Docker与腾讯云网页验收，发现并修复1项实际缺陷，修复后已部署并完成线上全流程复测。业务依据为现行 `docs/business/10-student-flow.md` 第9.3、9.4节及教师对应规则。

## 根因及修复

腾讯云免测通过后刷新页面、快速发起校队申请，界面误报“你的选课状态不是在读，无法执行该操作”。实际成员关系正常；课程数据尚未返回时，表单已可操作，提交处理器从空工作区查不到在读课程，于是直接在前端报错，未发送申请创建请求。

使用真实 `/class-sections` HTTP响应延迟回送进行本地复现：当时 `isLoading=true`、课程数0，前端错误出现，申请POST数0；放行原样响应后同一账号在读课程数1。没有伪造响应或更改成员关系。

修复 `frontend/student/js/screens/services.js`：课程与申请数据加载期间显示加载提示，数据完整后才初始化申请表单；提交处理器增加同样的加载保护，防止旧控件事件提前执行。源码提交 `26fc80e2423a6f94d673eca728985278980c5b9a`。未修改免测、认证、计分规则或后端权限。
