# 结算报告存储与迁移恢复验证

当前 Draft 仍为 239 个操作。本轮新增第 56 项迁移，为正式结算后续接口提供不可变报告版本存储，尚未开放正式结算命令，也没有把现有预检查的 UNAVAILABLE 改成通过。

报告版本存储保存课程、组织、已确认名单、教师历史主体、报告 JSON、数据库计算的 SHA-256、请求关联和时间。初版为第 1 版；更正版必须填写原因并引用同课程最新前版。数据库拒绝改写/删除历史、跳版本、错误前版、跨组织/课程名单和非责任教师写入。JSON 结构检查拒绝 null 绕过；摘要在插入触发器中计算，不能由调用方声明替代。新迁移固定 LF，避免 Git 换行转换改变 SQL 摘要。

综合名单服务新增同事务读取方法，仍在方法内校验责任教师范围，原预览接口继续使用 RepeatableRead。后续正式结算应在同一组织/课程锁和数据库事务内检查待办、读取完整名单、存报告及写事件，不能先预览后直接依据过期结果确认。

- `docker-settlement-storage-final-20260908.txt`：Docker 构建、56 项迁移、就绪 200、6 项迁移兼容测试、内部成绩 HTTP/CSV 名单确认/XLSX 导出、报告不可变/范围/摘要/前版/并发测试通过，退出 0。
- `settlement-storage-migration-check-final-20260908.txt`：56 项静态检查通过；生成清单检查通过；`settlement-migration-tests-20260908.txt` 的 9 项防护测试通过。
- `settlement-browser-backend-refresh-20260908.txt` 与 `sql-browser-settlement-storage-20260908.txt`：持续浏览器后端更新，浏览器库 56 项有效迁移、0 份结算报告。正式业务未被测试插入污染。
- `browser-credit-after-migration56-20260908.txt`：重启后学生原 35 分钟计入事实与页面回读仍通过。

原始失败与修复：

1. `docker-settlement-storage-first-20260908.txt`：生成列表达式被 PostgreSQL 以 42P17 拒绝。改为插入触发器计算。`sql-settlement-failed-migration-state-20260908.txt` 确认本地 v81_runtime_test 没有新增表/函数且应用步数为 0，专用脚本核对后仅使用 Prisma resolve 标记该失败尝试已回滚；未删库、表或事实。
2. `docker-settlement-storage-retest-20260908.txt`：迁移成功但就绪 503。旧检查器 LIMIT 1 随机取到同名的已回滚记录。修复后忽略已回滚尝试，要求恰好一条未回滚且已完成的当前记录，仍拒绝缺失、未完成、重复有效记录和摘要不符。最终 Docker 实测数据库同时保留失败已回滚记录与成功记录，并且就绪 200。

存储专项直接写入合成报告，只证明数据库基础，不证明正式结算的业务许可。旧运行测试库中的这些报告属于专用夹具，不应作为学期切换依据。原始日志保留命令输出空白；源代码与手写文档空白检查单独通过。
