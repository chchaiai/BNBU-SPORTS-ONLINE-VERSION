# 结算及归档后的认可更正网页验收

2026-09-09。本轮使用两个独立合成组织、各一名学生和一门课程，对已实现的认可调整/撤销完成网页验收。后端为本地 Docker PostgreSQL 服务，教师及管理员使用原 Portal 页面。

## 实际流程与结果

1. 夹具明确提供历史课程规则、名单源及合成材料元数据。学生通过真实邮箱 OTP 接口提交认证，教师经真实接口批准 30/15 分钟认可；名单确认、原始体测及最终成绩经真实接口完成。
2. 教师在网页确认课程结算并下载 v1。普通结算场景保留原当前学期；另一场景由管理员在网页创建新学期并成功切换，教师网页显示原课程已归档。
3. 教师在原审核弹窗将认可调整为 15/30 分钟。测试让服务先成功提交、再丢失响应，刷新后恢复原请求，输入锁定、同键重放返回完全相同数据，只新增 v2。
4. 教师继续在原入口撤销认可，同样验证丢响应、刷新、原键恢复，只新增 v3。
5. 两个场景都实际点击下载 v1/v2/v3 XLSX，解析名单内的两类认可秒数，分别为 1800/900、900/1800、0/0。再次下载旧版本仍保留原值，v1 报告 SHA 相同。认可历史共三版，当前已撤销。

普通结算与归档场景的首次浏览器操作均通过；两张截图已目视检查。后续只读回读把各三份实际下载文件保存在忽略的 `.local/v81-browser-state/`，文件名分别以 `recognition-settlement-browser-report-` 和 `recognition-archived-browser-report-` 开头。该目录同时有测试凭据和请求回执，不纳入 Git。
