# 已批准认证认可分钟调整

2026-09-09。增加 `POST /activity-certification-applications/{id}/recognition-allocation-revisions`（adjustV81Recognition）。责任教师在原认证详情的审核结果选择“调整认可分钟”，复用两类小时输入和原因字段，当前历史自动回填；原页面结构和样式不变。

## 处理规则

- 仅本人组织、本人课程的已批准校队/社团认证；必须有当前有效认可量，NORMAL 模式、课程尚未结算、学期未归档。课程关闭后的原认证仍可调整。撤销后的认证不能借普通调整重新批准。
- 请求带原申请版本、非空原因和两类整数分钟；每类非负、不超过课程目标，包含其他有效认证的占用量，合计最多 1,200 分钟。所有相关变更在同一串行化事务中执行。
- 追加 ADJUSTED 认可事件、ADJUST_RECOGNITION 审核历史、应用事件、审计和学生通知；更新当前投影并重算进度。原申请理由、类型、组织名称、原受理时间和旧认可历史保留。
- 按账号/申请保存原操作类型、请求体及幂等键，网络结果不明时锁定原字段；刷新后恢复原请求，重放不会再增加版本。
- 0059 迁移扩展已批准认证的同状态版本变更并约束原受理事实不可改写；其他状态转移保持原约束。迁移清单、校验和、生成产物和安全扫描登记同步更新，SQL 使用 LF。
- 候选协议现为 253 个操作、59 个迁移；正式合同发布基线未变。新接口明确登记 404 越权/未找到响应。

## 失败与修复

1. 第 28 次 Docker 96/97：其他教师尚未首次改密，得到门禁 403，而测试预期资源范围 404。测试增加真实首次改密后再检查越权。
2. 首次网页请求返回 500：新审计元数据传入未允许的版本字段，触发 AUDIT_METADATA_KEY_NOT_ALLOWLISTED 并回滚整个事务。改为该审计类型允许的状态/课程字段；版本仍在业务事件与审核历史中。复测从原 0/0 分钟事实继续，没有人工回填成功。
3. 第 29 次 Docker 95/97：测试覆盖命令遗漏 migrate deploy，独立回归库仍 58 个迁移，健康检查拒绝；新接口缺少 404 响应声明，严格协议校验拦截。已补齐迁移清单和协议，并在第 30 次命令中先实际部署迁移。
