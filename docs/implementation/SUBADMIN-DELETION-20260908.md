# 分管理员删除实施接续

现行业务 30-admin-flow.md 第 4.4 节要求总管理员确认职责全部移交，并物理清除登录账号、凭据、会话、验证挑战、邮箱及当前资料；已完成业务和审计只关联不具登录能力的历史主体。用户暂缓的是学生注销与教师删除，分管理员删除仍在范围内。

当前数据库查询发现 users 上仍有当前资料、会话、幂等记录、恢复挑战、邮箱挑战、推送设备、偏好、权限、账号安全、运行日志下载凭证及注销挑战外键。auth_sessions 另有 refresh_tokens、幂等记录、push_devices 等引用。0046/0047/0049 已为业务事件保留历史主体。

新迁移 0054 修正分管理员清理时的两个阻塞：guard_push_device_mutation 和 guard_user_preference_mutation 原先一律禁止 DELETE。现只对仍存在且属于同组织的 ADMIN/SUB 当前账号开放 DELETE，保留其余角色限制以及原有全部更新校验。沿用 0049 的退休触发器保留无凭据历史主体，不修改历史事件。

Docker 验证 docker-subadmin-cleanup-foundation-20260908.txt 退出 0，54 迁移应用成功：合成分管理员偏好物理删除成功，历史偏好主体退休；总管理员偏好仍拒绝删除且事务回滚保留数据。同时重跑邮箱 OTP 建号、状态、资料和邮箱变更测试通过。推送设备清理分支尚未专项运行，不以偏好测试代替。

下一步实现总管理员删除事务及接口：同组织 SUB/版本/职责交接校验，按外键顺序清理当前凭据和资料，保留历史业务、审计及内部主体，并验证旧登录失效、列表移除、重放及历史查询。当前没有正式删除接口或页面接线，不能宣称删除功能完成。只在专用合成数据库中验证，未操作腾讯云或真实用户数据。

## 回执清理关联

发现资料还会存在于幂等回执的加密响应中。建号和资料更新成功现在写入 SUBADMIN/resourceId，验证码请求与验证成功写入 SUBADMIN_IDENTITY/resourceId；没有改变返回内容、重放语义或权限规则。删除事务应先收集关联挑战 ID，再清理这些加密回执和挑战。

docker-subadmin-receipt-references-20260908.txt 退出 0，四类成功操作的资源关联均被数据库断言验证，建号重放只保留一个建号回执；完整 OTP/资料/邮箱/状态专项一起通过。契约检查 236 操作通过。

旧实现产生的回执尚未自动补关联，不能只清理新格式即宣称完成账号资料删除。旧建号/资料更新可结合 v81_events.request_id 定位，旧验证码验证回执需要结合幂等 scope 生成规则或受控解密识别。后续删除实现必须覆盖这项兼容清理，不能通过删除所有管理员回执扩大影响范围。

## 删除接口及旧回执兼容

新增 POST /admin/subadmins/{id}/delete。NORMAL 下只允许总管理员删除同组织 SUB，并要求 expectedVersion 与 handoverCompleted=true；事务清理挑战、目标账号回执、推送与偏好、刷新令牌、会话、权限、安全资料、当前管理员档案及用户。历史主体退休，新增不含当前资料的 DELETED 事件。删除动作回执属于操作者，保留以支持成功重放。

旧回执按现有 SecureDigest 的 idempotency-scope 算法计算关联范围，限定组织和具体账号/挑战，不解密或输出缓存资料，也不删除其他管理员的无关回执。邮箱挑战先收集当前邮箱、已消费的历史邮箱和关联挑战，再清理其请求/核验/建号范围。

docker-subadmin-delete-receipts-20260908.txt 退出 0：教师拒绝、缺少交接拒绝、账号和档案不存在、会话计数归零、旧会话 401、历史主体退休、CREATED 保留且 DELETED 唯一、删除重放返回同一结果通过。测试主动清空已有回执资源关联模拟旧版本，再按原回执 ID 断言全部清理；非空回执集合断言避免空测试。契约 237 操作通过，54 迁移。

页面删除按钮仍待接线。推送设备专项、真实已处理反馈删除后查询以及跨组织/并发删除边界仍待补充，不以本次合成账号测试声称完整删除验收。持续运行的浏览器后端尚需刷新至新接口。
