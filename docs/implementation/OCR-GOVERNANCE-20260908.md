# OCR 服务治理交接

本轮补齐组织范围的 OCR 配置、版本历史、暂停/恢复与执行版本绑定。三端全部业务验收仍未完成。

## 可用接口

- `GET /admin/review-services/ocr`：当前配置来源、版本、启停、部署执行开关、系统模式，以及本组织保留任务的状态计数和时间摘要。
- `GET /admin/review-services/ocr/revisions`：不可变配置历史，支持 `limit`（1–100）和 `beforeVersion`。
- `POST /admin/review-services/ocr/revisions`：追加新配置；请求包含 `provider`、`region`、`timeoutMs`、`enabled`、`reason` 和 `expectedVersion`，并使用幂等键。

三个接口仅允许完成首次改密的总管理员，维护期间仍可用于服务恢复。分管理员的系统模式、全局规则权限不包含服务治理。保存配置不执行教师确认，不改变学生期限，不开启 AI 自动通过。

支持已有 Tencent Table V3 适配器或 DISABLED。Tencent 配置必须有区域，超时 1000–60000 毫秒；DISABLED 必须同时禁用并清空区域。接口不接受密钥或任意服务器地址，连接仍使用固定的腾讯 OCR 服务端点和 CVM 身份凭据。

## 数据与执行

0052 迁移新增 `v81_ocr_service_revisions` 和 `v81_ocr_execution_services`。配置按组织连续追加版本，不允许改删；执行快照绑定任务及领取版本，保存实际使用的服务版本、提供方、区域和超时参数，不保存密钥、图片或识别文字。

尚未保存治理配置的组织沿用部署配置，版本为 0；每次实际执行仍保存该次参数快照。保存后的组织使用最新治理版本。暂停阻止新的识别任务和后台领取，已经受理的原件、任务和教学事实继续保留。运行中的外部请求可能完成，但当服务版本变化或已暂停时，旧响应不写入识别结果；恢复后按原有租约规则重新领取同一任务，保存新的执行配置快照。

部署的 OCR 执行开关仍是独立门禁：当前代码要求部署配置为 `TENCENT_TABLE_V3` 且 `OCR_WORKER_ENABLED=true` 才运行后台处理器。仅在 API 中启用服务不会绕过该开关。状态响应分别给出 `runtimeWorkerEnabled` 和 `executionEnabled`，配置保存成功不等于工作进程启用或腾讯连接成功。

状态中的任务数字统计全部保留任务。一个失败任务后来被新任务成功重试，原失败任务仍计入 failed；该数字不等于尚未解决的页面数。外部连接状态固定报告 UNVERIFIED，自动通过样本验证报告 NOT_PROVIDED，OCR 正式事实仍必须由责任教师核对确认。

## 剩余依赖

真实 CVM 身份权限、腾讯服务可用性与费用/区域配置仍待部署环境验证。服务治理页面接线、跨组织管理员隔离的完整 HTTP 测试、更多暂停/重启/并发故障场景尚未验证。VLM 自动初审及本校真实样本验证不在本次 OCR 治理通过范围内，继续按用户决定先验人工审核。

本轮未修改前端、冻结 contracts 或业务权威文档。测试容器完成后停止，数据卷保留。整体目标及既有失败以 `ACCEPTANCE.md`、`ISSUES.md` 为准。
