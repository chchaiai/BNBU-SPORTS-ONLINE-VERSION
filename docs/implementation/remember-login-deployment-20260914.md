# 学生网页记住登录状态修复

用户补充要求：清除网页后再次访问网址，自动恢复登录。按关闭页面、再访问同一浏览器同一网址处理。浏览器设置中清除网站数据/Cookie会删除凭据，不能无凭据恢复身份。

## 实现

- 启动以持久保存的有效API凭据为准。页面session标记丢失、损坏或未写入时可重建，不再要求凭据和页面标记同时存在；随后用服务器身份资料重新填写学号和引导状态。
- 复用已有刷新令牌机制。网络异常保留会话并展示可重试状态；业务验证401不再由页面一律清除登录凭据。
- 服务端明确撤销/停用后正确结束加载并返回登录；此前API已推进会话代次，页面可能提前返回而停在加载中，本轮一并修复。
- 延迟到达的旧请求错误不能清除新登录的凭据，包括另一页面更换登录会话的情况。
- 用户主动退出、完整清除网站数据、凭据失效仍要求身份验证。没有新增设备指纹、隐藏Cookie或绕过登录验证的恢复逻辑。

## 策略边界

本轮只修改学生静态JS，不改变后端策略及数据库。已只读确认生产当前访问令牌15分钟、刷新最长30天、闲置7天。自动记住表示有效会话在关闭网页后可恢复，不是永不过期登录。不同浏览器、无痕模式或隔离的独立应用存储不保证共享登录。

- 新增记住登录10项，包含新模块实例恢复、页面标记丢失/损坏、服务端身份修复、断网、非终止401、停用/撤销、令牌刷新、旧请求与新登录竞争、清除数据/退出/过期边界。
- 与游泳提交和错误投影回归合计20/20；全部共107项前端检查通过。新增测试使用真实前端模块与合成网络响应，不代表真实浏览器卸载或真实学生免登录验收。
- 无数据库迁移、后端镜像更换或认证有效期放宽。
