# 管理员删除学生：实现与验收记录

## 已确认业务规则

2026-09-11 用户确认：删除学生账号并移出全部课程，不保留历史打卡、审核和学时记录。采用专用删除入口，复用现有 USER_ACCOUNTS 权限、组织范围、版本校验、幂等和审计能力。普通学生资料编辑仍不开放。

## 实现

- 管理端学生详情增加“删除学生账号”。必须输入学号和非空原因，并确认不可恢复的删除范围。
- `POST /admin/students/{id}/delete`：同组织管理员、USER_ACCOUNTS 权限、NORMAL 模式、最新学生资料版本；教师、无权限分管理员、跨组织调用均拒绝。
- 在同一事务中删除账号、凭据、登录会话、全部成员关系、运动会话、打卡、审核、学时、相关申请及成绩。仅遍历明确列出的业务表和实际外键，不操作整门课程或其他学生。
- 数据库迁移 0061 安装专用删除命令及精确行保护例外。日常历史写保护继续有效；迁移本身不执行学生数据删除。未知关联或未清完的数据使整个删除事务回滚。
- 已保存结算报告删除目标学生行，保持其他学生行的顺序和内容，并重算报告摘要。
- COS/MinIO 凭证使用持久清理队列：先删除对象，再在旧上传凭证失效后再次清理，防止迟到上传留下孤立文件。失败自动重试。
- 管理员删除审计与不具登录能力的历史主体标识保留。既有运维备份按既有保留和恢复制度管理，不因业务删除自动销毁备份。

## 本地真实验证

- 独立学生通过网页邀请入班、学校邮箱验证、拍照录像、记录运动并提交打卡。

- 刷新后学生列表和详情不存在；旧访问令牌失效；账号、成员、打卡、运动会话、凭证关联和登录会话归零；其他学生的数据指纹不变。
- 分管理员权限授予和撤回立即生效；无权限、教师、跨组织、错误学号、空原因和旧版本分别拒绝。
- 三组已有申请/审核/认证/凭证的学生执行事务回滚回归，关联清理成功，其他学生数据不变。
- 已保存结算报告的学生删除、其他行保护和摘要一致性通过；普通历史删除继续被数据库阻止。
- MinIO 证明照片、视频对象已消失；模拟迟到上传后再次清理通过。
- 61 个迁移在全新本地 PostgreSQL 数据库执行通过；迁移检查及其 10 项测试通过。
