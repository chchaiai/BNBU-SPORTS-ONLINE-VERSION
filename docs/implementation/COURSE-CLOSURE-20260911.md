# 课程关闭自动移出与学生名单修复（2026-09-11）

状态：完成本地真实 Docker 回归、腾讯云部署、线上浏览器和数据库验收。代码本地提交 `f87dba74f39dc2ad7198a79d037e47ab8831c1d7`；报告、工具与证据另行本地存档，不推送。

## 业务裁定与根因

用户确认：“关闭整个课程就直接移除所有学生。”关闭应结束全部有效成员关系，学生从当前名单消失，已有打卡、审核、成绩及关闭前服务器已接纳的业务保留。

诊断编号 `01a08f87-d71b-71a0-b8b9-3bea4dba7e4e` 对应 `getStudent` 读取资料时的 HTTP 404 / `USER_NOT_FOUND`。根因有两项：

1. 原关闭课程实现仅更新课程状态，没有结束其 ACTIVE 成员关系。
2. 教师网页加载历史 enrollment 后，无条件请求每个学生的当前资料；该资料接口按现行权限要求仍在本教师课程中有效在课。成员移出成功后，刷新再次读取旧成员即出现 404，整个名单刷新失败。原“全部”列表还把历史成员作为当前列表显示。

本次只读核查确认受影响教师的一门已关闭课程残留两条 ACTIVE 关系，另有一条已移出关系。没有删除学生账号或历史记录。

## 修复结果

- 课程关闭在现有幂等、可串行化事务中执行，复用组织锁。全部 ACTIVE 成员改为 REMOVED，结束时间取课程关闭时间，原因标记 `COURSE_CLOSED`，成员版本递增。
- 每条变化沿用现有 SYSTEM 成员事件、审计和 outbox；课程关闭审计记录移出人数。任一步失败则整笔回滚；原幂等请求重放不重复移出。
- 当前学生名单和统计仅计有效在课成员；历史页保留成员引用及原记录，隐藏关闭课程和已结束关系的“移出课程”操作。
- 历史成员不再调用无权读取的当前学生资料接口，使用“历史成员”引用。资料权限没有扩大，普通失败仍按现有机制报错。
- 仅由课程关闭自动结束的成员关系，允许关闭前合法建立的会话继续首次材料提交；普通单独移出、撤课、归档和关闭后新会话没有此例外。上传、普通提交与游泳材料受理同步使用该规则。
- 学生没有当前课程时，仍显示已有补证待办入口。课程关闭提示和业务文档已同步用户确认的规则。
