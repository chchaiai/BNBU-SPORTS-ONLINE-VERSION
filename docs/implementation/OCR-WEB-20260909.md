# 教师网页 OCR 接线与本地验证

2026-09-09。依据用户“确认”，仅在现有名单导入和体测弹窗内增加必要图片选择、识别草稿与原图核对内容。整体三端目标继续进行。

## 实现

- 共用 OcrImportPanel 接入图片批次上传、历史批次翻页、逐页识别任务、结果刷新、原图读取、选择表/表头/字段列、创建草稿、逐行修改与核对、名单快照和所选体测确认。
- PNG/JPEG/WebP源材料批次最多100 MB；客户端在映射后预检500人员行，并由服务器再次强制校验。原图通过带权限的接口读取，不提供学生下载。
- 教师查看对应原图后才能勾选已核对。修改内容会清除该行核对标记。可信度未知或低于80仅作界面提示，所有行仍须人工核对；不以该阈值自动批准或推断业务结果。
- 体测正式提交依据服务器的匹配与疑点结果；未保存草稿不能提交，已确认行不能编辑，未选择行继续待处理。
- JSON写入保存原请求键和内容；上传保存源内容指纹和原键，刷新后可选择相同图片重试。CONFLICT_REQUEST_IN_PROGRESS保留恢复意图。
- 名单弹窗原来在页面层级中被侧栏遮挡，现使用React Portal挂载到文档顶层，原尺寸/CSS/布局保留。关闭名单导入弹窗后刷新原页面数据。

## 可复现和运行状态

源数据、图片、凭据位于忽略目录 .local/v81-browser-state，不进入Git。脚本在tools/local-integration：seed-v81-ocr-web.mjs建立独立合成课程及两名学生；create-v81-ocr-web-images.mjs生成明确标注的PNG；v81-ocr-web-browser-probe.mjs执行真实网页写入；verify-v81-ocr-web.mjs核对数据库和学生HTTP；v81-ocr-web-readback-browser.mjs只读复核。

浏览器后端配置使用compose.v81-test.yml + compose.v81-browser.yml，端口3199；Portal localhost:3300，学生127.0.0.1:4274/student。测试时额外加入compose.v81-ocr-browser.yml：仅本地启动脚本可加载v81-browser-ocr-provider.mjs，严格要求v81_browser_test和显式开关，并只识别源SHA匹配的合成图片；未知图像直接失败。测试结束已去掉该额外配置并重建恢复默认OCR关闭，见[恢复日志](ocr-web-restore-default-20260909.txt)。

## 证据限制与后续

腾讯OCR识别响应为明确的提供方测试替身，图片存储、任务执行、权限、草稿与正式数据为真实本地链路。本轮未调用腾讯云OCR或COS，未验证本校真实手写样本，不能据此宣称云端识别准确率已验收。此前测试替身单元格跨度包含人为疑点，教师核对后确认；替身代码现已规范跨度，低可信内容仍保留。

当前网页接受WebP原图，但实际TencentOcrProvider只接收PNG/JPEG且有单图Base64大小限制；这是已发现的实现衔接项，后续须处理提供方输入转换/限制提示。多页、500行边界、任务失败恢复已有后端证据，网页本轮实测为每批单页两行。正式Contract发布兼容性和三端其余原始章节的最终验收仍待完成。
