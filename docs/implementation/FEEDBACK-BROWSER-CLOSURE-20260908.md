# 学生反馈网页处理闭环

管理员真实模式接入现有 `/admin/feedback` 列表、详情和处理接口。原有五列表格、筛选区域和 CSS 保留；反馈编号接上详情操作，复用既有 TicketDialog 处理弹窗。支持处理中、等待技术处理、已解决、已关闭及公开回复。详情显示历史，服务端版本冲突刷新详情后由管理员再次明确提交。

提交使用固定幂等键；同次提交并发点击被拦截。丢响应时保留原提交内容与键，原内容重试不会重复追加历史。结果未确认时不允许改内容另发请求；同页面关闭后重新打开会先重放确认未决提交。未决意图保存在当前组件内存，整页关闭/刷新后的恢复仍需补强，不能声明所有中断恢复已完成。

本地真实 Docker 后端、PostgreSQL、Mailpit，Edge 浏览器验证：

- `browser-feedback-create-ui-final-20260908.txt`：学生邮箱 OTP 登录，从“我的 → 设置 → 问题反馈”提交。
- `browser-feedback-admin-ui-final-20260908.txt`：管理员点编号打开原有弹窗并公开回复；模拟服务器提交成功后丢失响应，同键重试通过，只增加一个版本、一条处理历史；再次同键重放和刷新回读通过。
- `browser-feedback-student-ui-final-20260908.txt`：学生重新登录，通过 API 与“我的反馈”页面读到 IN_PROGRESS 和公开回复。
- `feedback-wiring-typecheck-final-20260908.txt`：Portal TypeScript 退出 0。

较早 API 创建/回读、管理员浏览器首测与重试日志一并保留。`browser-feedback-lost-response-20260908.txt` 的 RELOAD 失败是测试按唯一文本定位重复的合成历史回复；补充历史条数/版本断言并修正定位后复验通过。学生 UI 创建两次超时由于测试漏点“设置”，无写请求；补齐真实路径后通过。没有删除既有反馈或历史来重跑测试。

本轮测试账号与内容为合成数据。实际学校邮箱投递、整页丢响应恢复、更多状态组合的浏览器验证及全部三端功能仍待完成。后台状态转换、越权和跨组织历史测试证据沿用对应专项，不能仅用此次 IN_PROGRESS 验证代替全部状态验收。
