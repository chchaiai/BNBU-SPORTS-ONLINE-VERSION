## 实施顺序

1. 核对四份业务文档、所有三端服务调用和已有基础后端，建立接口覆盖及差异清单。
2. 协议与迁移：补充课程规则快照、材料版本、审核轮次、补证计时、计入投影、结算及治理数据；学校日历按用户答复排除。
3. 后端基础：账号/邮箱/权限、课程/邀请/成员、学期、审计、对象存储。
4. V8.1：真实计时、材料硬校验、人工/AI 技术队列、一次补证、维护暂停、最优计入、名单/OCR、内部成绩与结算。按本轮确认先验收人工审核闭环。
5. 完成管理员服务及网页 API 接线；只改服务、协议和运行配置，不改变界面布局。
6. 独立领域规则先留存本地 Docker 验证证据；完整实现后继续迁移、接口、权限、并发与三端业务闭环测试。各批次测试发现的问题登记在 ISSUES.md，保留重现证据，不进入自动修复循环，也不以局部通过替代最终验收。
7. 交付运行方式、验证结果、依赖及交接记录，审核明确路径后本地 Git 存档。
