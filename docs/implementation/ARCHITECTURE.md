## 服务与数据职责

现有三端网页通过 `/api/v1` 调用同一 NestJS API。页面布局保持现状，服务层负责令牌、版本号、幂等键和真实响应映射。学生、责任教师、总管理员和分管理员权限必须由后端核验，页面隐藏按钮不能代替权限检查。

CVM 承载 API 与后台任务。先采用单一后端工程及 PostgreSQL 事务，不增加独立消息系统。补证逾期任务根据服务器时间、正式受理事实、当前模式和维护区间执行，事务锁保护终结结果。后续多副本运行仍须以数据库状态为准，不能以进程内定时器作为唯一事实。

PostgreSQL 保存身份、班级成员、规则版本、运动会话、材料版本、审核、补证、计入投影、通知与审计。材料包和事件追加后不可修改，规则发布后锁定。计入结果可根据有效记录及认证认可重算，历史运动时长和已受理材料不随投影重算而改写。

COS 保存私有材料字节，数据库只保存对象引用与服务器校验结果。现有工程提供 S3 兼容适配器及 CVM 角色凭据提供器；云端使用角色授权与短期凭据，受权上传/读取必须核对学生、会话和责任教师范围。上传成功、媒体校验通过、材料包正式受理、教师判定有效是不同阶段。

本地 Docker 使用独立项目，业务环境拟包含 PostgreSQL、MinIO、Mailpit、API 和原三端入口。MinIO 只验证对象存储交互，不代表腾讯 COS 的角色授权和跨域策略已经通过；Mailpit 只验证本地验证码收取，不代表真实学校邮箱投递成功。当前独立 domain-tests 服务仅执行纯领域规则测试，禁用容器网络，并使用只读根文件系统及临时目录。

## 本轮业务决定

- 总管理员明确开启指定班级的人工模式，由责任教师完成有效、无效或一次退回补证。AI 未经真实样本验证时不自动通过。
- 依用户答复，排除学校统一工作日日历及其 SLA 验收；保留教师轮次事实。
- 模式仅 NORMAL/MAINTENANCE。维护预计恢复时间只作公告，实际恢复必须由授权管理员操作。
- 学生补证时限按实际维护/故障区间去重暂停；逾期终结前必须复核正式受理事实。
- 学生不得取得内部成绩、换算分或排名。旧投影和网页接线仍需逐项核对，此项尚未验收。

需要正式 COS 桶、区域、CVM 角色及桶内前缀权限、上传跨域配置、PostgreSQL 连接与可信 CA、发信服务配置。教师邮箱按用户决定允许自定义有效邮箱，不要求固定学校域名。凭据不写入本文、Git 或普通日志。本轮不连接云端业务数据、不执行云端部署。
