# 当前香港服务器有界容量测试方案

用户于 2026-09-11 授权真实部署环境阶梯测试，并确认典型场景：学生查首页、进度、记录、运动状态为主，少量教师查名单与记录。独立合成组织标识以 `BNBU-TEST-PERF-` 开头。

## 基线和负载

- 仓库初始 HEAD `8432a7a061f75885f546eaa4bd24070e4a2afa52`，分支 `codex/bnbu-sports-web-new-20260907`，初始工作区干净。
- 目标 `43.129.193.7`，CVM 2 CPU，约 3.57 GiB 操作系统可见内存；数据库 `172.19.0.16:5432`。测试开始时部署目录为 `3957d4249031-continuity`。
- 外部 Windows Node.js 发压，固定解析到确认的 CVM IP，正常 HTTPS 证书校验、Keep-Alive。真实链路为公网 → Nginx → 当前 Backend → PostgreSQL。
- 建立 200 个独立合成学生，另有测试教师和管理员，课程含 200 个真实入班关系及已发布 V8.1 规则。会话签发仅为夹具准备，不声称邮箱 OTP 或登录容量验收。
- 请求比重目标：90% 学生读取，10% 教师读取。学生涵盖 me、enrollments、records、active session、student-progress、notifications、proof-todos；教师涵盖 20 条分页名单、记录列表。
- 常规阶梯：1、5、10、20、40、80、120、160、200 个活跃用户，每人每 5 秒一个请求，各 60 秒。由于网络响应和发压结束后的等待，实际吞吐以测量值为准。
- 突发阶梯在前面通过后单独执行：取消思考时间、仍保持最多 200 并发及 150 RPS 上限；定位持续延迟上升点。无法触达极限时只能报告已验证下界。
- 稳态复核：选择通过的高负载档持续 5 分钟；写操作单独有界验证开始、暂停、继续、取消，并检查数据库残留状态。

## 自动停止条件

1. 单轮最多 600 秒、200 个虚拟用户、150 RPS（令牌桶最多 5 个突发令牌），每请求 6 秒超时。
2. 10 秒窗口至少 20 个请求时错误率超过 1%，或连续两个有效窗口 p95 超过 2 秒，停止本轮及后续升压。
3. 主机 CPU 连续 3 次采样超过 85%，可用内存低于 500 MiB，后端内存超过容器上限 85%，立即停止。
4. 健康检查失败、容器重启/OOM/不健康、数据库锁等待、监控失联或过期，立即停止。
5. 请求停止后等在途请求退出，核验恢复；异常档不得当作稳定容量。

## 监控和证据

主机/容器约每 5 秒采样 CPU、可用内存、网络字节、网络丢包、负载、容器内存/CPU/状态及本机 readiness；数据库独立单连接采样连接状态、等待事件、事务/读写累计值、缓存块、锁等待、死锁和临时空间。

发压端保存每请求时间、类别、状态、延迟和响应字节数；不保存正文、账号、令牌或密钥。每 10 秒输出延迟/错误汇总和发压端事件循环延迟。

现有应用未暴露连接池 waitingCount，数据库端活动会话只能近似反映池占用，不能直接证明应用排队长度。云监控 CPU API 返回 `AuthFailure.UnauthorizedOperation`；不扩大现有角色权限。`pg_stat_statements` 未安装，不能提供逐 SQL 执行耗时排名。

## 数据边界

写入仅发生在新建的合成组织；保留审计和测试事实。完成后停用这些账号并增加 tokenVersion，核验无开放运动会话。既有真实组织不参与写入压测。OCR、真实邮件、批量 COS/视频上传不属于用户确认的本轮典型高峰模型。

课程名单有真实 200 条；首轮历史记录列表为空。首轮结束后增加 2,000 条明确标注的合成数据库历史记录，每学生 10 条，其中 8 条 VALID、2 条 PENDING_TEACHER，并包含 review/workflow/credit projection。这些是假造容量夹具，不是实际运动事实，也不是上传审核全链路验收；真实请求读取这些数据。填充后从 20 人重新逐级升压。

不得把未观察到的故障极限、托管数据库 CPU 或未测试的媒体容量写成实测结果。增加本机回环的学生进度和教师名单探针，用于辅助区分应用处理与公网往返时间；此探针每 5 秒各一次，独立于业务发压计数。

## 执行中的有界调整

- 写入阶梯为 1、5、10、20 人，每人依序 start/pause/resume/cancel，不执行无上限写入。
- 持续请求阶梯开始前，通过真实 API 开始 60 个合成运动会话；教师记录请求改为真实 `reviewResult=PENDING` 条件，覆盖有数据的待审列表。
- 突发阶梯每档 30 秒。40 个持续并发出现 4 次超时后，阶梯直接停止，80/120/160/200 突发档未执行。
- 除窗口停止阈值外，stairs 在每档结束后遇到任何错误也不再升压。200 人带历史档的单次超时和 40 突发档均触发该保守规则。先核验恢复与服务器日志，再开展低负载测试。
- 稳定复测采用 200 个独立合成学生、每人约 3.333 秒一个请求、持续 300 秒，目标约 60 RPS，低于已出现平台与错误的约 94 RPS。所有原硬上限和资源停止阈值继续有效。
