## 详细决策说明

### ADR-006：直接入班而非教师审批

- 决策原因：阶段指令明确学生填写姓名、学号、性别和年级后直接加入；当前 Android 与业务文档也已迁移到该流程。
- 后端不变量：邀请凭证有效、教学班开放、身份字段有效、同一学生/教学班不重复、同一学期冲突规则通过后，原子创建或返回学生身份、`Enrollment` 与登录会话。
- 兼容：不删除未知远端的旧申请 API；先统计调用、冻结新增、处理存量，再下线。

### ADR-011：打卡状态与审核结果分离

- `ExerciseRecordStatus` 表达草稿、提交、审核流程和取消。
- `ReviewResult` 只表达 `PENDING/VALID/INVALID`。
- 修改已审核结果不是覆盖原行，而是追加新 `ReviewRecord`，并触发累计时长与成绩重算。
- 这会改变现有“提交即有效”的语义，属于高风险兼容迁移，必须在客户端迁移矩阵中显式处理。

### ADR-017：20 小时与双目标配置（已拆分）

阶段 4 指令已经冻结总计算资格门槛为 20 小时，因此原 ADR-017 不再把“总门槛”和“分类配额”混成一个选择。ADR-061 接受 72000 秒总门槛；ADR-062 继续等待 course/general 两类如何分配及由谁配置。未确认 ADR-062 前，客户端可展示服务端总进度，但不能把 Android 的 20/10/10 默认值或 Web 配置 Mock 当成正式分类规则。

### ADR-025：Greenfield 权威后端基线（已接受）

- 权威方式：不继承、修复或猜测未知远程实现，在根仓库当前分支的 `backend/` 普通目录内 Greenfield 新建。`backend/` 不作为 Git submodule。
- 旧远程 API：定义为未知遗留黑盒；不作为 schema、接口、认证或业务实现依据，不连接或修改其数据库。兼容 Adapter 只在后续客户端迁移阶段按调用遥测决定；没有遥测前不得宣称旧接口可删除。
- 数据库：PostgreSQL 18。初始 migration 是新数据库的 Greenfield baseline，不存在需要伪造或导入的历史表、schema 或 migration history。
- ORM 与 migration：使用与 Node.js 24、PostgreSQL 18 兼容的 Prisma 当前稳定版；数据库结构只能由 `backend/` 中的版本化 migration 变更。
- 应用技术栈：NestJS 当前稳定版、TypeScript strict、Node.js 24 LTS、npm，采用 Docker 容器化模块化单体。
- API：REST JSON，唯一前缀 `/api/v1`；`docs/backend-contracts/openapi.yaml` 是唯一人工维护的 API 机器合同，后端实现和客户端都服从该合同。
- 环境事实：当前没有已建立的 staging 或 production 数据，也没有 Greenfield 后端的 production 部署。完成 Foundation 不能被表述为已上线或已通过生产验收。
- 版本证据（2026-08-02 核验）：Node.js 24.18.0 LTS、NestJS 11.1.28、Prisma 7.9.1、PostgreSQL 18.4；最终依赖由 `package-lock.json` 锁定，容器使用精确版本标签。

### ADR-042 / ADR-043：角色基数与教学责任（已被 ADR-077 替代）

V1 已正式选择“一个 User 一种基础角色/对应 Profile”和“一个 ClassSection 一个责任 `teacherId`”。未来多角色、协同教学、代课或交接不是 V1 隐含能力；如获批准，应新增显式关系对象及其状态、有效期、授权范围和审计，不得把多个 ID 塞进字符串或 JSON 字段，也不得扩大现有 `ADMIN` 固有权限。

### ADR-067：V1 Course 目录治理与教学班责任（已接受）

- 历史：本 ADR 此前为 `PROPOSED`，因此 Course POST/PATCH 只保留 transport 并稳定返回 `COURSE_WRITE_DISABLED`；该形成过程和历史错误码继续保留用于审计与旧消费者识别。
- 接受日期：2026-08-03，阶段 11 项目负责人明确批准 V1 方案。
- Course 是组织级、跨学期复用的目录定义，`CourseStatus` 冻结为 `ACTIVE/INACTIVE`。只有同组织 `ADMIN` 可创建、修改、启用或停用；`courseCode` 创建后不可变。停用不关闭或删除已有 ClassSection，但阻止新开班。
- `TEACHER` 可读取本组织 ACTIVE Course，不能写 Course；只能在 ACTIVE Course 和可写 Semester 下创建本人负责的单教师 ClassSection，并仅修改/关闭本人班。`teacherId` 从 principal 的 TeacherProfile 解析，不能由请求体扩权。
- `ADMIN` 可读取本组织 ClassSection 治理投影，但默认不能创建、修改、关闭或代行教师教学操作。`STUDENT` 的 Course/ClassSection 可见性必须经 ACTIVE Enrollment 解析；Enrollment Gate 前不得返回组织全量目录或假空成功。
- 未来学校教务同步是允许的数据来源，但必须新增受信系统身份/同步 ADR，并复用同一个 Course application service、表、唯一约束、审计与 Outbox；本阶段不实现连接器。

### ADR-075：Greenfield 技术架构（已接受）

- 单一部署单元使用 ESM 模块化单体；模块之间通过显式应用服务、Port 和事务边界协作，不共享未定义的内部表语义。
- 需要跨模块原子性的写入使用 PostgreSQL 事务；业务事务只写领域状态、AuditLog 与 Outbox，不在事务中同步调用外部服务。
- 初期不引入 Kafka、RabbitMQ，也不把 Redis 设为运行前提。幂等记录和 Outbox 均先使用 PostgreSQL 持久化；未来是否拆分必须由容量、延迟和运营证据重新决策。
- 对象存储只暴露 S3-compatible Port。local 使用 MinIO；生产供应商由环境适配决定，业务代码不得直接绑定腾讯云 COS、AWS S3 或其他厂商 SDK。
- 不采用完整 Event Sourcing。`ReviewRecord`、`ScoreAdjustment` 等 append-only 业务历史只是特定领域事实和审计要求，不代表以事件重建全部系统状态。

### ADR-076：分层实施门禁（已接受）

- **Greenfield Foundation Gate**：只允许工程骨架、配置、数据库连接与 migration、Organization、SystemMode、User/Profile、AuthSession/RefreshToken、Semester、requestId、响应 envelope、错误映射、认证守卫、权限策略框架、幂等、AuditLog、Outbox、健康检查、日志和测试基础设施。
- **Business Module Gate**：Course/ClassSection、Enrollment/QR Join、Roster、ExerciseSession、MediaEvidence、ExerciseRecord、Review、Score、Export 必须分别完成对应合同与业务决策后实施，不创建返回假成功的空接口。
- **Production Gate**：Token 生命周期、密钥托管轮换、备份恢复目标、媒体安全与保留、幂等参数、日志审计告警责任、staging、production Secret、域名 HTTPS、数据生命周期、隐私和法务事项全部明确并验证后，才可声称生产就绪。
- 阶段 9 的原始“不可以开始完整后端实现”结论保留。Foundation Gate 的推进只缩小了可实施范围，不改变其余门禁状态。

### ADR-077 至 ADR-085：V1 合同闭合（已接受）

- 身份与教学责任：V1 只使用 `STUDENT/TEACHER/ADMIN` 单基础角色、单对应 Profile 和单一 `ClassSection.teacherId`，不预埋含义不完整的数组或 Assignment。
- 审核：删除 claim operation、`CLAIM_REVIEW` 和可写 `UNDER_REVIEW`。Record 状态闭集为 `DRAFT/SUBMITTED/REVIEWED/CANCELLED`；并发审核由双版本、ReviewRecord 唯一约束和事务处理。
- 权限：OpenAPI 每个 operation 的 `x-access-policy` 是机器权威，`05-permission-matrix.md` 第 11 节是生成 registry；双向缺失和重复均为构建失败。
- 入班：公开预览和资料验证后签发一次性 Join Capability；普通 Access Token 不能替代它。明文只返回一次，持久化仅保存不可逆摘要；完整 Join 留到 Enrollment Gate。
- 范围：Foundation 只建立核心体育打卡必要依赖，不把 Web Mock 批量升级为表，也不创建返回假成功的业务 Controller。
- 目录：ReviewReasonCode、ScoreAdjustmentReasonCode 与 ExportType 使用本轮指定的闭集及 i18n key；冻结类型不表示 ScoreAdjustment 或 ExportJob 已实现。
- 关闭能力：已保留 transport 的未批准能力必须声明稳定 deny error，在任何写入、任务、签名 URL 或外部副作用之前失败。

### ADR-086：确定性物理与安全投影合同（已接受）

- ID 在应用层生成 UUIDv7、PostgreSQL 使用 `uuid`；所有 API 消费者仍把 ID 当不可解析的 opaque string。
- ExerciseRecord 每日唯一键唯一使用 `(enrollmentId,businessDate)`；V1 的 CANCELLED 不释放槽位，任何改变必须新增 ADR 和 migration。
- 系统创建的初始 PENDING ReviewRecord 可令 `teacherId=null`；教师 VALID/INVALID 必须非空；`reason` 500、`internalNote` 2000。
- MediaEvidence 在申请上传时分配稳定 `mediaId` 并进入 PENDING_UPLOAD；确认沿用该 ID。客户端声明 hash 与服务端验证 hash 分开，只有后者是完整性事实。
- AuditLog 使用已冻结的精确字段、append-only repository 和安全摘要，不保存原始幂等键、IP、设备指纹、secret、PII、storage key、签名 URL、媒体正文或 internalNote 正文。
- 学生 `currentReview` 仅包含 `result/reasonCode/publicComment`，不复用包含教师内部字段的 ReviewRecord projection。

### ADR-087 / ADR-088：Foundation 物理枚举与认证基线（已接受）

- 所有持久化业务状态使用 `varchar/text` + 明确命名的 CHECK constraint；Prisma schema、SQL migration、07 枚举和 OpenAPI named enum 必须同值。此选择不允许应用写入未知字符串。
- 密码使用 Argon2id；Access Token 由受维护的 JOSE 实现进行非对称签名，并只包含 `sub/organizationId/role/sessionId/jti/tokenVersion/iss/aud/iat/exp`。
- Refresh Token 是高熵 opaque secret，数据库只保存摘要并记录 parent/replacement/consume/revoke/reuse 事实；轮换与 reuse detection 必须在同一 PostgreSQL 事务完成。
- ADR-088 不批准任何生产 TTL、密钥托管供应商或浏览器长期 Refresh Token 存储方式；这些仍由 ADR-022、ADR-072 和 Production Gate 阻塞。

### ADR-089：TypeScript 兼容性基线（已接受）

依赖解析实测显示 TypeScript 7.0.2 与当前稳定 `typescript-eslint 8.65.0`（peer `<6.1`）及 `openapi-typescript 7.13.0`（peer `^5.x`）冲突。为同时满足严格类型、ESLint、确定性安装和禁止 `--force/--legacy-peer-deps`，Foundation 固定 TypeScript 5.9.3。OpenAPI 的 policy/validator metadata 由仓库内无第二合同的确定性生成器产生；未来升级 TypeScript 7 必须先证明 NestJS、ESLint、生成器、Prisma 和全部测试兼容。

### ADR-090：Nest Swagger 安全版本例外（已接受）

2026-08-02 的锁文件审计显示 `@nestjs/swagger` 11.4.6 通过 `js-yaml` 5.2.1 引入 GHSA-pm4m-ph32-ghv5 高危解析 DoS；npm 的非强制修复指向 11.4.5。Foundation 因此精确固定 11.4.5，并只用它展示从权威文件加载的合同，禁止由 decorator 生成第二份 OpenAPI。该例外在上游发布无漏洞稳定版后复审升级。

### ADR-091：Foundation 内部持久化状态闭集（已接受）

- Organization 与三类 Profile 当前只批准 `ACTIVE`；不猜测 `INACTIVE/ARCHIVED` 等生命周期。未来组织停用或 Profile 归档必须先补业务规则和 migration。
- AuthSession 使用 `ACTIVE/REVOKED/EXPIRED`。只有 `REVOKED` 携带撤销时间与原因；过期由服务端权威时间判断，不等于撤销。
- IdempotencyRecord 使用 `IN_PROGRESS/COMPLETED/RETRYABLE_FAILURE`，并由数据库约束 lease、完成时间和稳定响应的字段组合。具体 retention 与 lease 数值继续由环境配置和 Production Gate 阻塞。
- OutboxEvent 使用 `PENDING/PROCESSING/PROCESSED/FAILED`，数据库约束领取锁与完成时间的状态形状；领取重试策略和运营告警阈值不在此 ADR 中决定。
- 这些技术状态不增加任何体育业务模块能力。所有未知值 fail closed；扩展闭集必须同时更新 ADR、Prisma、自定义 SQL migration、状态机测试与运行时代码。

### ADR-092：Foundation JOSE 签名 profile（已接受）

- Foundation Access Token 只使用 `EdDSA` 与 Ed25519 密钥；私钥输入为 PKCS#8 PEM，公钥输入为 SPKI PEM。服务启动时必须用配置密钥执行一次签名/验签探针，算法或密钥不匹配时立即失败。
- 验证端固定允许 `EdDSA`，并继续严格检查 issuer、audience、过期时间以及 ADR-088 的精确 claim 白名单；不接受客户端指定算法，不提供对称密钥或弱算法回退。
- 本 ADR 只闭合 Foundation 的密码学实现 profile。production 的密钥托管、轮换责任、`kid`、旧公钥保留窗口、应急吊销和浏览器 Refresh Token 传输仍未批准，继续受 ADR-072 与 Production Gate 阻塞。

### ADR-093：QR Join 凭证与专用重放 escrow（已接受）

- CourseInvite 与 JoinCapability 都使用 `UUIDv7 publicId.secret` transport。secret 由密码学安全随机源生成，数据库长期只保存使用独立 `QR_JOIN_TOKEN_HASH_KEY` 计算的 HMAC；验证使用常量时间比较。公开 ID 不是授权凭证，知道 ID 不能替代 secret。
- `createCourseInvite` 与 `issueJoinCapability` 的通用 PostgreSQL 幂等记录只保存不敏感的 `inviteId` 或 `capabilityId`。为精确重放首次 token 响应，领域行保存用途绑定的 AES-256-GCM ciphertext、key version 和明确的 replay expiry；普通 projection、AuditLog、Outbox 与日志均不得读取或返回这些字段。
- 当前 OpenAPI 的 Join operation 不重新提交身份字段，因此 capability 使用同一专用 AEAD 加密规范保存规范化身份 snapshot。只有 Join use case 在重新验证 invite/capability/ClassSection 安全上下文后解密。
- 成功 Join 的 Access/Refresh Token bundle 只进入 JoinCapability 的专用 result escrow。通用幂等响应只保存 capability 引用；只有相同 capability、identity fingerprint、operation 与 Idempotency-Key 的重放可恢复该结果。到期清除 ciphertext 不删除 capability 消费、Enrollment、Session、审计或领域事件事实。
- 所有 QR Join TTL、HMAC key、AES key 与 public rate-limit 参数都必须显式配置并 fail fast；本地合成值不构成 production 参数批准。ADR-070/072 与 Production Gate 保持未闭合。

### ADR-094：V1 学生身份与 Enrollment 生命周期（已接受）

- 学生身份 key 是同 organization 内保留前导零的规范化 `studentNumber`。`fullName` 执行 trim + Unicode NFC；gender 与四位 gradeYear 严格校验。系统不按姓名、拼音、联系方式或近似值合并身份，也不自动覆盖现有 Profile。
- QR Join 在一个 Serializable PostgreSQL 事务内锁定 capability，创建或严格复用 STUDENT User/StudentProfile，校验同学期 ACTIVE 唯一，创建 ACTIVE Enrollment 与 append-only status event，建立 AuthSession/RefreshToken，消费 capability，并写 AuditLog、Outbox 和专用 result escrow。任一步失败全部回滚。
- 永久唯一 `(classSectionId, studentId)` 表达同一关系；恢复更新同一 enrollmentId。相同幂等请求可精确重放；新的请求遇到同班 ACTIVE 返回 `ENROLLMENT_ALREADY_ACTIVE` 且不得新建 Session，遇到 REMOVED/WITHDRAWN 返回 `ENROLLMENT_REJOIN_DISABLED`。
- 学生 QR Join 必须要求 ACTIVE Course/ClassSection、可写 Semester 与 `isEnrollmentOpen=true`。责任教师手工添加只允许已存在的同组织 ACTIVE StudentProfile，要求本人教学班、可写状态与非空 reason；公开加入开关不限制教师受审计的成员管理，也不会建立新的 AuthSession。
- Teacher 只能读写本人 ClassSection 的 Enrollment；ADMIN 只能本 organization 只读；STUDENT 只能读取本人关系。学生 Course/ClassSection projection 只能由 ACTIVE Enrollment 导出。
- ADR-054 仍为 PROPOSED。真实 withdraw route 在 policy/self scope 后稳定返回 `ENROLLMENT_WITHDRAWAL_DISABLED`，不写状态事件、成功审计或业务 Outbox；学生自行恢复同样不开放。

### ADR-095：V1 Official Roster 文件、版本和对齐运行剖面（已接受）

- FILE 导入只接受扩展名 `.csv`、MIME `text/csv`、内容为严格 UTF-8 的文件；允许且只允许一个 UTF-8 BOM。CSV 标题和 field mapping 使用白名单，所有单元格按纯文本处理，以 `= + - @` 开头的公式样式值不得作为有效业务值。XLSX、XLS、ODS、ZIP、PDF、图片、OCR、远程 URL 与邮件附件均不属于 V1 合同。
- 一个 Import 版本的统计满足 `totalRowCount = validRowCount + invalidRowCount + duplicatedRowCount`。重复和无效行作为不可变 Entry 保留；只有 `VALID` Entry 参与对齐，且至少存在一条 VALID Entry 才能将 Import 发布为 `VALIDATED/current`。
- `OfficialRosterEntry` 永不保存或更新平台匹配外键；Enrollment/StudentProfile 的匹配只存在于带 `algorithmVersion`、`comparisonRevision` 和冻结平台快照的不可变 Run/Result 中。名单、对齐、处置或 rollback 都不得创建、删除或修改 User、StudentProfile、Enrollment。
- `RosterAlignmentRunStatus` 固定为 `RUNNING/COMPLETED/FAILED`；`RosterResolutionAction` 固定为 `CONFIRM/RESOLVE/REOPEN`；V1 可验证证据固定为 `NEW_ALIGNMENT_RESULT/ENROLLMENT_STATUS_EVENT/OFFICIAL_ROSTER_VERSION`，且引用必须真实存在、同组织并在责任教师资源范围内。
- OpenAPI 增加 current version 读取与 rollback 两个真实 operation；rollback 使用当前 Import ID + optimistic version 做原子比较后切换指针，只允许责任教师。Roster 读取允许 Admin 在本组织获得最小只读治理投影，所有 mutation 仍只允许责任教师。
- `OFFICIAL_API` 枚举只保留未来兼容语义；没有受信 Connector 前，FILE route 上的该 source 稳定返回 `ROSTER_IMPORT_SOURCE_UNSUPPORTED` 且不产生 Import。ADR-045 的 production retention、ADR-057 的新 IGNORED 能力和 ADR-070–074 的 production 参数均未被本 ADR 批准。

- `MediaEvidence.businessPurpose` 增加 `EXEMPTION_APPLICATION`。该用途必须绑定本人 ACTIVE Enrollment、存入私有对象路径，并只能关联同一学生/组织/Enrollment 的免测申请；公共投影不返回 storageKey、签名 URL 或 `internalNote`。
- 本地/test 可使用受限的验证码投递适配器。非 test 环境未配置真实短信/邮件 provider 时必须返回 503，禁止通用验证码。本 ADR 不授权 Staging/Production 部署。
- 本决策不批准通知业务生产者、APNs/FCM provider 或投递 worker，不证明 Staging HTTPS、iOS 二进制真实 API 闭环或 Production Gate，不允许生产 GPS。后续隔离的本地 Docker Synthetic Staging 运行证据已记录在 `21-client-capabilities-local-integration-report.md`，但它不改变上述外部门禁；帮助/版本政策也没有管理端发布流程或已批准生产内容。

### ADR-099：15 秒有声打卡视频与客户端压缩（2026-08-09，ACCEPTED）

- 每条 ExerciseRecord 最多关联 1 个现场 VIDEO；视频累计实际录制时长必须大于 0 且不超过 15 秒。暂停期间不累计，可继续录制、提前结束，达到 15 秒必须自动结束。
- Android 使用 App 内相机并同时录制声音；相机或麦克风权限缺失时不得开始录像。完成后必须先在本机压缩，压缩失败保留原始本地草稿供重试或重拍，不得上传未压缩文件。
- 源格式、文件大小、分辨率、码率由设备和客户端兼容层决定，不作为业务拒绝条件。`mimeType/fileSizeBytes` 仍作为传输和完整性事实，服务端仍拒绝损坏、伪造或无法安全解析的媒体。
- 后端不信任客户端声明时长，确认与处理阶段均以媒体字节探测的真实时长裁决；超过 15 秒进入 FAILED 并返回 `MEDIA_VIDEO_DURATION_EXCEEDED`。Record 仍必须等待媒体 AVAILABLE 才能提交。
- ADR-099 只替换 ExerciseRecord 视频规则；图片数量/大小、免测附件、反馈附件、媒体权限、保留和访问控制均不改变。
- 新错误只登记在实际可能返回它的媒体 operation `x-error-codes` 中，不扩散到所有 API 的公共 `ErrorCode` 枚举；合同门禁以基础枚举与 operation 扩展的并集校验后端唯一错误词表。

### ADR-100：统一完成说明与全量现场凭证（2026-08-11，ACCEPTED）

- 课程相关运动与自主运动在完成记录阶段都只收集一个必填 `description`，长度为 1..200 字；不再提供或写入学生补充备注。
- 运动结束后仍可在 App 内补拍照片或有声视频；视频继续遵守 ADR-099 的 15 秒、暂停不计时和压缩后上传规则。
- Android 不再展示凭证勾选框。上传前仍可删除或重拍错误素材，但提交时仍保留的全部 Ready 草稿都必须上传并进入凭证集合。
- 后端以同一学生、同一 session、`EXERCISE_RECORD`、`IN_APP_CAMERA` 为范围裁决完整集合；任何处理中媒体都阻止提交，任何 AVAILABLE 媒体被遗漏或额外 mediaId 被加入都拒绝提交。
- 媒体申请、绑定和 Record 提交共同锁定 session；Record 不再是可编辑草稿后，不得为该 session 新增或绑定媒体。
- `student_remark` 先从业务合同、投影和读写代码移除，数据库遗留列保持不可访问；物理删除必须等待破坏性迁移审批和兼容窗口。

### ADR-101：邮箱唯一认证与短信能力下线（2026-08-11，ACCEPTED）

- 学生仅使用组织范围内已验证邮箱的一次性验证码登录；教师与管理员的密码登录和账户找回也只按已验证邮箱查找。请求中的 `channel` 为兼容邮箱客户端继续保留，但闭集固定为 `EMAIL`，`PHONE` 必须在校验层稳定拒绝且不得创建挑战或投递消息。
- 新建学生账户进入 `PENDING_CONTACT_BINDING`。该状态只允许读取本人信息、请求/验证邮箱、刷新会话和退出；邮箱验证成功后原子进入 `ACTIVE`，才能访问其余业务能力。
- 本人邮箱首次绑定只验证新邮箱；更换已验证邮箱必须分别验证当前邮箱和新邮箱。成功换绑保留当前调用会话并撤销其他设备会话。验证码、邮箱明文和凭据不得进入日志、AuditLog 或 Outbox。
- `/me` 联系方式占位 PATCH 删除，改为 `POST /me/email-verification-challenges` 与 `POST /me/email-verification-challenges/{challengeId}/verify`。公共 User 投影不再包含任何手机号或手机号验证字段。
- 既有手机号数据库列、唯一索引和历史 `PHONE` challenge 作为遗留审计事实保留，Prisma 应用映射标记为不可读写；本阶段不 DROP、不清空、不修改历史 Migration。未来物理删除需独立破坏性迁移审批。
- 非测试环境验证码投递仅允许显式 SMTP 邮件适配器；Staging/Production 缺少完整 SMTP 配置时启动失败。仓库不得保存 SMTP 密码，本地与测试使用隔离邮件服务或内存捕获适配器。
- Android 登录页和“账户与安全”只保留邮箱流程；删除手机号输入、短信验证码、短信绑定和手机号恢复入口。无法使用邮箱时仅提示联系管理员核验并补录邮箱。

### ADR-102：扫码入班资料的性别与年级稳定校验（2026-08-11，ACCEPTED）

- 学生通过二维码加入课程时，性别只接受 `MALE` 或 `FEMALE`；Android 仅展示“男/女”二选一，后端在加入能力 DTO 层稳定拒绝 `OTHER`、未知值和缺失值。
- 全局 `Gender.OTHER` 继续保留给历史学生资料、官方名单和其他既有投影，不迁移、不清空存量数据，也不借本决策收窄全局枚举。
- `gradeYear` 表示四位 cohort 年份，统一按整数 `1000..9999` 校验；不再使用当前年份、课程年份、固定 `2027` 或“当前年 + 1”作为上限。
- OpenAPI 为加入课程请求使用专用 `CourseJoinGender`，Android 与后端在同一 monorepo 变更中同步升级；旧客户端若继续提交 `OTHER` 将收到稳定校验失败。
- 本决策不改变邮箱绑定、验证码、会话激活、名单历史数据或数据库结构，不需要 Migration。

### ADR-103：跨端运动说明、WebM 与位置元数据边界（2026-08-12，ACCEPTED）

- 本 ADR 仅取代 ADR-100 中“课程相关与自主运动说明均必填”的一句。`GENERAL` 自主运动必须提交 trim 后 1..200 字的 `description`；`COURSE_RELATED` 可省略或提交 null，非空值仍须 trim 后 1..200 字。`studentRemark` 移除、全部现场凭证绑定和提交后冻结规则不变。
- `exercise_records.description` 由 forward-only Migration `0016_optional_course_exercise_description` 改为 nullable，并由数据库 CHECK 同时约束 `credit_type` 与说明；后端领域层仍执行同一规则，不能只依赖客户端显示。
- ExerciseRecord 视频允许的传输声明为 `video/mp4`、`video/quicktime`、`video/3gpp`、`video/webm`。后端必须核对真实容器、SHA-256、字节数、可信时长和轨道；所有容器仍须至少一个视频轨和一个音轨，真实时长必须大于 0 且不超过 15 秒。
- WebM 直接按原始 EBML/WebM 字节验证，不引入浏览器端 FFmpeg/WASM，也不把 WebM 伪装成 MP4。照片继续作为所有支持现场相机的客户端必备凭证路径。
- 上传凭证不要求 GPS/EXIF 位置。iOS、Web、Android 不得为了上传照片或视频申请定位权限或主动采集经纬度。后端识别到 GPS IFD、EXIF 位置或容器位置标签时返回 `MEDIA_LOCATION_METADATA_NOT_ALLOWED`，不把位置提取成业务事实。
- 本 ADR 不开放 6 个 GPS/位置 HTTP operation，不批准定位采集、真实性判断、地图、保留期或 Production Gate；Staging HTTPS、真实邮箱投递和真机媒体闭环仍需独立环境验收。

### ADR-104：免测结构化明细与扫码入班 bootstrap 顺序（2026-08-14，ACCEPTED）

- `applicationType` 继续使用 `PHYSICAL_TEST`、`EXERCISE_CHECK_IN`、`SPECIAL_CIRCUMSTANCE` 三类稳定运输值；新增 `applicationSubtype` 精确区分 `RUN_800M`、`RUN_1000M`、`SCHOOL_TEAM`、`STUDENT_CLUB`、`SPECIAL_CIRCUMSTANCE`。
- `SCHOOL_TEAM`、`STUDENT_CLUB` 必须单独保存 trim 后 1..128 字的 `organizationName`；其他 subtype 的 `organizationName` 必须为 null。`reason` 只保存学生理由，不再拼接组织名称或用自由文本代替 subtype。
- forward-only Migration `0017_exemption_application_details` 新增两个可空列。历史申请无法可靠反推 subtype，保持 null 并在投影中明确为 legacy；禁止按学生性别、reason 或客户端旧枚举伪造回填。
- 更新后的 iOS/Android 新建与修改必须发送结构化明细，后端校验 applicationType/subtype/organizationName 组合。为兼容已经完成的 Contract 1.5 客户端，三项明细同时省略的旧请求仍可保存为 legacy null；不得只发送其中一部分。`PHYSICAL_TEST` 与 `EXERCISE_CHECK_IN` 在提交审核前必须至少关联一份同 Enrollment、状态为 AVAILABLE 的私有免测材料。
- `enrollmentId` 保留为必填权威归属，用于唯一责任教师、ClassSection、媒体范围和学期边界；客户端应从后端 ACTIVE Enrollment 中明确选择，不得用 courseId、学号或本地默认值替代。
- 公开 Join Capability 是普通 Access Token 出现前的受限预认证凭证。新学生 join 成功后得到 `PENDING_CONTACT_BINDING` 会话，只能访问本人信息、邮箱 challenge、refresh 和 logout；邮箱验证转为 `ACTIVE` 后才可进入运动、免测等受保护业务。两阶段顺序不构成身份冲突。
- 本 ADR 不启用 APNs/FCM，不修改通知隐私政策，也不证明 Staging HTTPS 或生产投递。iOS 可先使用本地 Docker、Mailpit、MinIO 与合成数据完成真实 API 闭环。

### ADR-105：打卡提交默认有效与教师异常否决（2026-08-17，ACCEPTED）

- 学生成功提交 ExerciseRecord 时，后端在同一事务中将 Record 从 `DRAFT` 直接置为 `REVIEWED`，并创建 `reviewVersion=1`、`result=VALID`、`teacherId=null` 的系统 ReviewRecord；该记录立即按服务端裁决的 `creditedDurationSeconds` 进入成绩重算。
- 教师端不再把新记录作为逐条待办。Web 默认展示全部已提交记录及其当前 `VALID` 结果；风险提示只用于发现异常，不产生审核事实。
- 责任教师发现问题时，可通过既有 review mutation 在双版本校验、权限校验、事务、AuditLog 和 Outbox 保护下，从当前 `VALID` 直接追加下一版本 `INVALID`；Record 保持 `REVIEWED`，旧 VALID 行不可修改或删除，并立即移除该记录的成绩贡献。
- 为兼容切换前的存量数据，`SUBMITTED + PENDING -> REVIEWED + VALID/INVALID` 和 reopen 流程继续可用；新提交不得再隐式生成 PENDING。`PENDING` 保留为历史兼容及显式重开状态，不是新记录默认值。
- 本 ADR 取代 ADR-011、ADR-019、ADR-056、ADR-078 中关于“所有新提交必须先 PENDING 并由教师逐条确认”的部分；ReviewResult 与 Record 流程状态分离、append-only 历史、责任教师边界和只有当前 VALID 贡献成绩的其余规则不变。
