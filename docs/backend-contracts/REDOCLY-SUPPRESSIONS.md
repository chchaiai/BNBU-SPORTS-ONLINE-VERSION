# Redocly suppression register

Every entry in `tools/backend-contracts/.redocly.lint-ignore.yaml` is narrow and intentional. The lint command still runs the recommended ruleset and must report zero unsuppressed warnings.

| Rule                     | JSON pointer               | Reason                                                                                                                                                                                                                | Removal condition                                                                |
| ------------------------ | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `operation-4xx-response` | `getHealthLive` responses  | Public liveness has no authentication or client-controlled business input. Its real outcomes are 200 or 500; inventing a 4xx response would misstate runtime behavior.                                                | A real client-error branch is introduced and covered by HTTP conformance.        |
| `operation-4xx-response` | `getHealthReady` responses | Public readiness has no authentication or client-controlled business input. Its real outcomes are 200 or 503.                                                                                                         | A real client-error branch is introduced and covered by HTTP conformance.        |
| `operation-4xx-response` | `getSystemMode` responses  | The public projection has no request input. Its real outcomes are 200, 500, or 503.                                                                                                                                   | A real client-error branch is introduced and covered by HTTP conformance.        |
| `no-unused-components`   | `ResponseMeta`             | Published Contract 1.3 exposed this component by name. Removing it would be a needless component-level compatibility break while existing envelopes use the more specific `SuccessMeta` and `PagedMeta`.              | A major contract version removes the deprecated compatibility component.         |
| `no-unused-components`   | `ScoreContribution`        | Published Contract 1.3 exposed the traceability schema by name, but no public operation returns internal contribution rows. Keeping it avoids a component-level compatibility break without leaking score provenance. | A major contract version removes it or an approved privileged operation uses it. |
