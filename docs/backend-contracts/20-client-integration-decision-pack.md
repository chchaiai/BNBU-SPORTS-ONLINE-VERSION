## 批准决议（取代下方表格中的待批准占位）

下方决策表保留 Stage 20A 审批前的选项、证据和风险快照；其中 `USER_APPROVAL_REQUIRED` 单元格是历史占位，不再代表当前状态。项目负责人已批准每项推荐方案，并同时批准独立纯合成 staging 的有限建设范围。

- 联调顺序：Auth → Teaching / Enrollment → Session / Media / Record → Review → Score；各模块 Android 学生端优先，随后 Web 教师/管理员端。
- Client：generated DTO/schema + handwritten transport；三端模型必须绑定同一 OpenAPI commit/hash。
- 环境与认证：显式 local/staging/production 注入；Android Keystore-backed encrypted storage；Web Secure HttpOnly SameSite refresh cookie + memory access token，其浏览器细节需 staging 安全验收；未来 iOS Keychain。
- 共同协议：只按 error `code` 分支；按合同使用 idempotency/version；Session、Media、Record、Review、Score 资源顺序与后端事实保持权威。
- Mock：测试 fixture 与显式 development-only 入口可保留；production 中 Mock、seed、本地业务事实、旧 API fallback 必须不可达。
- 验收：独立 synthetic staging、private Media、安全 reset、Score/Audit/requestId tracing；Export 仍为 `SYSTEM_MODE_UNSUPPORTED`。
- 边界：这不是 staging 运行就绪证据，不批准 Export、Production、真实数据、Historical Data Migration、iOS 工程或三端完成。

## 当前客户端证据

- Android 是 Kotlin/Compose 学生端，有手写 OkHttp/Gson client、旧 `/api` base URL 和大量旧 endpoint/DTO；release 要求 HTTPS，但 debug 默认仍指向旧 IP。只保存一个加密 bearer token，没有权威 refresh family 流程；有显式 Mock 用户、本地 workspace/session/media 草稿。
- Web 是教师/管理员交互原型，主要业务状态位于 `localStorage/sessionStorage` Mock service；任意非空账号密码即可进入，管理员 session 是本地 30 天标记。Roster 自建路径、状态枚举和 CSV export 与权威 OpenAPI 不一致；没有统一真实 API client/base URL/token refresh/cursor/error adapter。
- 仓库内没有 iOS 工程，因此 iOS 只能定义未来合同，不能进入实际联调完成口径。
